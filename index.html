    Something failed?

    Sign-in page won't load

    Campus or office Wi-Fi may block our server. Sign in once on a phone hotspot, then tell John which network failed. Don't change proxy, DNS, or firewall settings.

    Connected, nothing works

    Expected until John assigns your device group. Send him the device name and NetBird IP.

    “Invalid credentials”

    Almost always the wrong email. Use exactly the address John invited (for example your work address, not Gmail, and not a shortened or lengthened version of your name). Only that address has an account. Need a different address? Ask John for a new invitation.

    IP doesn't start with the range John gave you

    The app is signed in to a different NetBird network (usually the default NetBird Cloud, or a Google/GitHub account). Disconnect, set the server to the address at the top (step 3), and sign in with the lab account John invited. Then send the new IP.

    Certificate warning

    Stop. Check the address matches the bar at the top, then ask John. Never bypass it.

    VPN permission denied

    Disconnect Tailscale or any other VPN on the phone, then tap the NetBird button again and allow the VPN prompt.

    “Command not found”

    Finish the install and open a new terminal window (PowerShell as Administrator).

    “System extension blocked”

    Open System Settings → Privacy & Security and allow NetBird, then try again.

    Ping fails

    Ping is blocked on purpose. Test the service John approved instead.

    Send John your device, the step number, and the error text. Never send passwords, codes, invitation links, or private keys.

    SSH after John grants access

    John gives you three values: host, port, OS username. Use your own existing key.

    On a phone use an SSH app (Termius, JuiceSSH, Blink) with those values.
